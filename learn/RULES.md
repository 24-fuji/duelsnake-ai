# DuelSnake ルール

学習環境 (`learn/src/env/`) と Web 版 (`web/src/game/`) の両方が従うゲームルールの仕様です。
数値は [config.yaml](config.yaml) の既定値で、括弧内はその設定キーです。設定を変えた場合は読み替えてください。

## 1. 概要

- 2人対戦のスネークゲーム。各プレイヤーは自分専用のフィールドで自分のヘビを操作します。
- 2つのフィールドは独立しており、相手に影響を与える手段は「お邪魔」アイテムだけです。
- 制限時間は 30 秒 (`game.grid.time_limit_seconds`) です。
- 壁・自分の体・お邪魔ブロックにぶつかると、その時点で負けです。

## 2. フィールドと時間

- 大きさは 16 × 16 マス (`game.grid.width`, `game.grid.height`) です。
- 座標は左上が (0, 0) で、x は右、y は下に向かって増えます。
- ゲームは 0.1 秒 (`game.grid.tick_seconds`) ごとの「ティック」単位で進みます。
- 秒で指定した値は、すべて四捨五入してティック数に変換します (例: 0.6 秒 → 6 ティック)。
- 制限時間の 30 秒は 300 ティックです。

## 3. ヘビ

- 初期状態は長さ 3 (`game.snake.initial_length`) です。頭は (8, 8)、つまり (幅/2, 高さ/2) にあり、胴体は下へ (8, 9), (8, 10) と伸びていて、上向きです。
- 通常は 0.2 秒 (2 ティック、`normal_speed_interval_sec`) ごとに 1 マス進みます。最初の移動は 2 ティック目です。
- ブースト中は 0.1 秒 (1 ティック、`boost_speed_interval_sec`) ごとに 1 マス進みます。

## 4. 操作

| 行動 | 内容 |
|---|---|
| `up` / `down` / `left` / `right` | 次に移動する方向を変える |
| `boost` | ブーストを発動する (使用可能なときだけ) |
| `use_item` | 所持アイテムを使う (持っていなければ何も起きない) |

- 方向は移動の合間に何度変えてもよく、最後に受け付けた方向へ次の移動で進みます。
- **直前に実際に進んだ方向の真逆は無視します。** 判定の基準は「直前に進んだ方向」なので、上に進んでいる最中に「左 → 下」と素早く入力しても下は無視され、反転して自滅することはありません。

## 5. ブースト

- 発動すると 5 秒間 (50 ティック、`boost_duration_sec`)、移動間隔が短くなります。
- ブーストが終わると 7.5 秒間 (75 ティック、`boost_cooldown_sec`) のクールダウンに入り、その間は発動できません。
- ブースト中やクールダウン中に `boost` を入力しても何も起きません。

## 6. アイテム

| アイテム | 盤上の数 | 取ったときの効果 | 再出現まで |
|---|---|---|---|
| 普通のリンゴ | 3 (`max_apples`) | スコア +1、長さ +1 | 0.6 秒 (`apple_respawn_delay_sec`) |
| 金のリンゴ | 1 | スコア +3、長さ +3 | 1.0 秒 (`special_respawn_delay_sec`) |
| 毒リンゴ | 2 (`max_poison`) | スコア -1、長さ -2 | 0.6 秒 |
| ブロック消去 | 1 | 所持する | 1.0 秒 |
| お邪魔 | 1 | 所持する | 1.0 秒 |

- アイテムは、頭がそのマスに入ったときに取得します。
- 取ったアイテムは、再出現までの時間が経つと同じ種類のものがランダムな空きマスに出ます。空きマスとは、ヘビの体・アイテム・お邪魔ブロックのどれも無いマスのことです。空きマスが無い場合は、空くまで毎ティック出現を試みます。
- 試合開始時の配置も、ランダムな空きマスです。両プレイヤーのフィールドはそれぞれ独立に配置します。
- スコアは 0 未満になりません。

### 長さの増減

- **伸びる**: 伸びる量が「伸びる予定」に加算されます。アイテムを取った次の移動から、1 回の移動ごとに尻尾が縮まないことで 1 マスずつ伸びます。
- **縮む (毒リンゴ)**: まず「伸びる予定」を打ち消し、それで足りない分だけ尻尾を即座に削ります。長さは 1 より短くなりません。

### 所持アイテム

- 所持できるのは 1 つだけです。持っている状態で別の所持アイテムを取ると、新しいほうで上書きします。
- **ブロック消去**: 使うと、自分のフィールドにあるお邪魔ブロックをすべて即座に消します。
- **お邪魔**: 使ってから 0.2 秒後 (2 ティック後、`jam_block_delay_sec`) に、相手のフィールドのランダムな空きマスにお邪魔ブロックを 1 つ置きます。
  - 相手の頭からマンハッタン距離 2 以内 (`jam_block_safe_distance`) には置きません。これで、避けようのない位置にブロックが出ることを防ぎます。
  - 置ける場所が無ければ、そのブロックは消滅します。
- お邪魔ブロックは、ブロック消去で消されるまで残ります。

## 7. 移動と衝突

ヘビが 1 マス進むときは、次の順に処理します。

1. 進む先を、頭の位置から現在の方向へ 1 マス先とする。
2. 進む先が盤の外なら死亡する。
3. 進む先がお邪魔ブロックなら死亡する。
4. 進む先が自分の体なら死亡する。ただし伸びる予定が無いときは、尻尾のマスはこの移動で空くので入ってよい。
5. 頭を進める。伸びる予定があれば 1 減らし、無ければ尻尾を 1 マス縮める。
6. 進んだマスにアイテムがあれば取得する (6章)。

## 8. 1ティックの処理順

1. ティック数を 1 増やす。
2. 両フィールドで、再出現待ちのアイテムと届く途中のお邪魔ブロックのタイマーを 1 減らし、0 になったものを出現させる。
3. 両プレイヤーの入力 (方向・ブースト・アイテム使用) を反映する。人間の入力は、前のティック以降に押されたものを押した順にすべて反映する。
4. 両フィールドで、ヘビのタイマー (ブースト残り・クールダウン・次の移動まで) を 1 進め、移動するヘビは 7章の処理を行う。
5. 勝敗を判定する (9章)。

「d ティック後」に起こるものとしてティック t に登録された出来事は、ティック t + d の手順 2 で起こります。

## 9. 勝敗

| 状況 | 結果 |
|---|---|
| 片方だけが死亡 | 死亡した側の負け (スコアは関係ない) |
| 同じティックで両方が死亡 | スコアが高い方の勝ち。同点なら引き分け |
| 300 ティック目の終わりに両方とも生存 | スコアが高い方の勝ち。同点なら引き分け |

## 10. AI の入出力

学習済みモデルを Web 側で動かすための仕様です。実装は学習側が `learn/src/env/observation.rs`、Web 側が `web/src/ai/observation.ts` と `web/src/ai/model.ts` です。

### 行動を決めるタイミング

AI が行動を決めるのは、**自分のヘビが次のティックで移動するとき** (「次の移動まで」のタイマーが 1 のとき) だけです。決めた行動は、その次のティックの入力 (8章の手順 3) として使います。
通常は 2 ティックに 1 回、ブースト中は毎ティック行動を決めます。それ以外のティックでは入力しません。

### 観測

AI 自身のフィールドから見た、盤面 (9 × 16 × 16) と状態ベクトル (13) の 2 つを入力します。盤面は `[チャネル][y][x]` の順に並べます。

| # | 盤面チャネル | 値 |
|---|---|---|
| 0 | `own_head` | 自分の頭のマスが 1 |
| 1 | `own_body` | 頭を除く胴体。頭から数えて i 番目 (頭 = 0) の値は (長さ − i) / (長さ − 1)。首が 1 で、尻尾に向かって小さくなる |
| 2 | `normal_apple` | 普通のリンゴが 1 |
| 3 | `gold_apple` | 金のリンゴが 1 |
| 4 | `poison_apple` | 毒リンゴが 1 |
| 5 | `block_clear_item` | ブロック消去アイテムが 1 |
| 6 | `block_jam_item` | お邪魔アイテムが 1 |
| 7 | `obstacle` | お邪魔ブロックが 1 |
| 8 | `in_bounds` | すべてのマスが 1 (畳み込みでの盤外の 0 と区別するため) |

| # | 状態ベクトル | 値 |
|---|---|---|
| 0–3 | `dir_up`, `dir_down`, `dir_left`, `dir_right` | 直前に進んだ方向の one-hot |
| 4 | `pending_growth` | min(伸びる予定 / 5, 1) |
| 5 | `held_block_clear` | ブロック消去を所持していれば 1 |
| 6 | `held_block_jam` | お邪魔を所持していれば 1 |
| 7 | `boost_remaining` | ブーストの残りティック / 50 |
| 8 | `boost_ready` | ブーストを発動できれば 1 |
| 9 | `time_remaining` | 残りティック / 300 (残りティック = 300 − 現在のティック数) |
| 10 | `score_diff` | clamp((自分のスコア − 相手のスコア) / 10, −1, 1) |
| 11 | `opponent_holds_jam` | 相手がお邪魔を所持していれば 1 |
| 12 | `incoming_jams` | min(自分に向かっている途中のお邪魔ブロック数 / 3, 1) |

正規化に使う定数 5, 10, 3 は、モデル JSON の `observation.*_scale` にも書き出しています。

### 出力

`up, down, left, right, boost, use_item` の順に並んだ 6 個の Q 値を出力し、最大のものを行動として選びます。
難易度を下げるときは、`difficulty[].random_action_rate` の確率でランダムな行動に置き換えます。

## 11. モデル JSON の形式

学習すると `model/recent-model/snake-model.json` が更新され、`model/models/` にはタイムスタンプ付きのバックアップが残ります。
重み配列だけは 1 行にまとめて出力し、それ以外は整形して人が読める形にしています。

| キー | 内容 |
|---|---|
| `format`, `format_version` | 常に `"duelsnake-dqn"` と `1` |
| `created_at`, `training` | 作成日時と、それまでの学習量 (試合数・判断数・更新回数) |
| `game` | 学習時のゲームルール (config.yaml の `game` と同じ構造) |
| `observation` | 観測チャネル・特徴量の名前と正規化定数 |
| `actions` | 出力の並び |
| `difficulty` | 難易度ごとのランダム行動率 |
| `network.conv[]` | 畳み込み層。`weight` は `[out_channels][in_channels][kernel_size][kernel_size]` を平坦化したもの |
| `network.dense[]` | 全結合層。`weight` は `[out_features][in_features]` を平坦化したもの |

順伝播は次のとおりです。

1. x = 盤面
2. 各 `conv` 層で次を計算し、ReLU をかける (範囲外の入力は 0 とする)。

   `out[oc][oy][ox] = bias[oc] + Σ weight[oc][ic][ky][kx] · x[ic][oy·stride + ky − padding][ox·stride + kx − padding]`
3. x を `[チャネル][y][x]` の順で平坦化し、その後ろに状態ベクトルを連結する。
4. 各 `dense` 層で `out[o] = bias[o] + Σ weight[o][i] · x[i]` を計算する。最後の層以外は ReLU をかける。

## 12. 学習時の報酬

学習時の報酬は次のとおりです (config.yaml の `reward`)。

- 試合終了時: 勝ち +1、負け −1、引き分け 0
- スコアが 1 点増減するごと: ±0.1

学習は 2 匹が同じネットワークで戦う自己対戦です。両方の視点の経験を学習に使います。
